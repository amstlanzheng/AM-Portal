## ADDED Requirements

### Requirement: 用户注册
系统 SHALL 支持用户通过用户名和密码注册账号，注册后状态默认为"待审核"。

#### Scenario: 用户注册成功
- **WHEN** 用户提交用户名、密码、邮箱进行注册
- **THEN** 系统创建用户记录，状态为"待审核"，密码使用 BCrypt 加密存储

#### Scenario: 用户名已存在
- **WHEN** 用户使用已存在的用户名注册
- **THEN** 系统返回错误提示"用户名已存在"

#### Scenario: 注册信息校验
- **WHEN** 用户提交的注册信息不符合规则（用户名为空、密码过短、邮箱格式错误）
- **THEN** 系统返回校验错误信息

### Requirement: 用户登录
系统 SHALL 支持用户名登录，登录成功后返回 JWT Token。

#### Scenario: 用户名密码登录成功
- **WHEN** 用户使用正确的用户名和密码登录
- **THEN** 系统返回 JWT Access Token 和 Refresh Token

#### Scenario: 账号待审核
- **WHEN** 待审核状态的用户尝试登录
- **THEN** 系统返回错误提示"账号待审核，请等待管理员审核"

#### Scenario: 账号被禁用
- **WHEN** 被禁用状态的用户尝试登录
- **THEN** 系统返回错误提示"账号已被禁用"

#### Scenario: 密码错误
- **WHEN** 用户输入错误密码
- **THEN** 系统返回错误提示"用户名或密码错误"

### Requirement: 用户审核
系统 SHALL 支持管理员审核注册用户，通过后账号启用，拒绝后账号禁用。

#### Scenario: 管理员审核通过
- **WHEN** 管理员将待审核用户状态改为"启用"
- **THEN** 用户可以正常登录

#### Scenario: 管理员审核拒绝
- **WHEN** 管理员将待审核用户状态改为"禁用"
- **THEN** 用户无法登录

### Requirement: 用户信息管理
系统 SHALL 支持用户修改个人资料（昵称、邮箱、手机、头像），支持管理员管理所有用户。

#### Scenario: 用户修改个人资料
- **WHEN** 登录用户修改自己的昵称、邮箱、手机号
- **THEN** 系统更新用户信息

#### Scenario: 用户修改头像
- **WHEN** 用户上传新头像
- **THEN** 系统将头像上传至 MinIO，更新用户头像 URL

#### Scenario: 管理员管理用户
- **WHEN** 管理员查看用户列表、修改用户状态、设置管理员角色
- **THEN** 系统执行相应操作并返回结果

### Requirement: 用户数据模型
用户实体 SHALL 包含以下字段：用户名、密码（BCrypt）、昵称、邮箱、手机（可选）、头像、创建时间、状态（待审核/启用/禁用）、是否管理员。

#### Scenario: 用户数据完整性
- **WHEN** 创建或更新用户记录
- **THEN** 所有必填字段必须有值，密码必须 BCrypt 加密，状态必须为合法枚举值
